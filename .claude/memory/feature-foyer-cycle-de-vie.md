Diagnostic clé : `svc-foyer` sait DÉJÀ tout éditer (`PUT /foyers/:id`, CRUD parents, events NATS). Cause profonde du blocage = autorisation : toutes les écritures BFF sont `@AdminSeulement()` → en prod (auth active, `FOYER_AUTHZ_ENFORCE=1`) le parent prend **403**. Les gardes sont déclaratives (`APP_GUARD` globaux) → passer `@AdminSeulement()`→`@FoyerScope('param:id')` suffit (admin bypass conservé). Manque aussi : `PUT /api/v1/foyers/:id` au BFF (absent) + `mettreAJour` au foyer.client + écran web de modif.

Décisions tranchées (toutes = reco) :

- **(1bis)** création **self-service** de la 1re fois + garde **create-once** (non-admin avec foyer existant → 409), créateur auto-rattaché comme parent. ⚠ change le provisioning admin-only déployé.
- **(2)** garder le modèle **0/1/N foyers** (familles recomposées) — create-once limite la self-création, pas le rattachement multi-foyers.
- **(3)** enfants en **édition + suppression** (events `EnfantModifie`/`EnfantRetire` à créer ; couplage contrat↔enfant par prénom libre inter-services = pas de cascade plannings, désynchro cosmétique seulement).
- **(parents)** un parent gère les parents de SON foyer via `@FoyerScope`.
