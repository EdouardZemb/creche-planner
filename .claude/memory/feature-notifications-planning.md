Feature lancée 2026-06-24 : chaque mardi, notifier le parent pour valider le planning de la semaine suivante (email + indicateur in-app) ; si modifs → brouillon récap relu puis mail au service concerné (crèche / école ABCM).

Plan complet approuvé sur disque : `C:\Users\edoua\.claude\plans\gleaming-finding-castle.md`.

**Décisions utilisateur** : canal = email parent + in-app ; mail service = relecture avant envoi ; destinataire = adresse PAR établissement ; portée = ENVOI RÉEL en prod (→ dry-run par défaut, allowlist, traçabilité).

**Divergences clés** : (1) PAS de mode « ABCM » — `MODES_CONTRAT=['CRECHE_PSU','PERISCOLAIRE','CANTINE','ALSH']` ; ABCM = établissement regroupant les 3 derniers → mapping `mode→établissement` nécessaire. (2) Préavis « 3 j ouvrés » supposé mais le repo dit 2 j crèche (RM-03) / jeudi 12h ABCM (RM-07) → modélisé en paramètre `preavisRegle` par établissement. (3) Produit mono-foyer/démo → 1er envoi sortant vers un tiers réel = prudence.

**Architecture** : nouveau microservice `apps/svc-notifications` (6e service, base dédiée), consomme stream NATS `PLANIFICATION`, héberge état validation hebdo + config établissements + journal d'envois + scheduler du mardi (setInterval style outbox.relay, Europe/Paris, horloge injectable, idempotence via UNIQUE). Mailer = `EmailModule` (nodemailer) dans `libs/nest-commons`, importé seulement par notifications. SMTP réutilise le secret Gmail Alertmanager.
